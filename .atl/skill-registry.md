## Compact Rules

### issue-creation
- Follow issue-first workflow for Agent Teams Lite when applicable.
- Include repro steps, expected vs actual, environment for bugs.
- Link to code paths or commits when known.

### branch-pr
- Issue-first: branch and PR should reference an issue when the team uses that enforcement.
- PR description: complete sentences, scope, test plan.

### skill-creator
- Follow Agent Skills spec structure (frontmatter, triggers, clear steps).
- Keep triggers grep-friendly phrases.

### go-testing
- Prefer table-driven tests; use testify assert/require where it clarifies failures.
- For HTTP: httptest + gin context patterns consistent with existing handlers.
- Redis in tests: miniredis (already used in Arnela).

### judgment-day
- Only when user explicitly triggers phrases (dual blind review protocol).
- Two independent judges, synthesize, fix, re-judge; max 2 iterations then escalate.

### canvas
- Use for data-heavy / analytical artifacts; read skill when editing `.canvas.tsx`.
- Prefer canvas over huge markdown tables when skill applies.

### create-rule / create-skill / create-hook / create-subagent
- Match Cursor product conventions; do not over-scope generated files.
- Skills: triggers in description; keep SKILL.md maintainable size.

### update-cursor-settings
- Edit user `settings.json` only when user asks; confirm paths (Cursor vs VS Code).

### babysit
- PR-focused: triage comments, CI green, conflicts; loop until merge-ready.

### shell
- Prefer repo scripts; Windows vs Linux differences for Go `-race` / Docker.
